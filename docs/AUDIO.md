# Звуки частиц

Основной движок создаёт запросы в `SoundCueBuffer`, а `SoundCuePlayer` выбранной GUI-ветки проигрывает их через Minecraft. Дополнительный движок светлячков звуков не создаёт. Фон и выключенное взаимодействие также не создают новых запросов взаимодействия.

## Списки в профиле

В каждом списке случайно выбирается ID события:

- `captureSounds` — при захвате частицы мышью.
- `sweepSounds` — при смахивании.
- `shortSweepSounds` — необязательный короткий вариант.

Если `shortSweepSounds` отсутствует или пуст, `sweepSounds` используется и в полёте, и на опоре. Если короткий список есть, короткий звук используется в обоих состояниях, а обычный добавляется только для лежащей частицы. Такая короткая + обычная пара считается одним взаимодействием для глобального cooldown, но каждый реально проигранный клип занимает свой звуковой слот.

Пример `assets/mypack/sounds.json`:

```json
{
  "petals.sweep": {
    "sounds": ["mypack:petals/sweep_1", "mypack:petals/sweep_2"]
  },
  "petals.capture": {
    "sounds": ["mypack:petals/capture"]
  }
}
```

В профиль записывается `"sweepSounds": ["mypack:petals.sweep"]`; OGG лежат в `assets/mypack/sounds/petals/`. Minecraft сам загружает стандартный `sounds.json`. Everfall создаёт клиентские SoundEvent для ID, на которые ссылаются профили, не изменяя замороженный реестр после запуска. Встроенные события также регистрируются штатно при инициализации загрузчика.

## Громкость и скорость взаимодействия

Текущие базовые множители 1.0.0:

| Событие | Множитель |
|---|---:|
| Sweep лежащей частицы | 0,50 |
| Sweep летящей частицы | 0,20 |
| Capture | 0,55 |

Они умножаются на общую громкость Everfall из настроек. Значение 0 выключает проигрывание мода. Дополнительно действуют собственная громкость ресурса и настройки звука Minecraft.

Sweep появляется только при скорости взаимодействия выше 160 экранных пикселей в секунду, независимо от GUI scale и режима координат движения. Скорость меняет сам факт смахивания и физический импульс; она не является отдельным плавным регулятором громкости. Одно касание неподвижным курсором не должно создавать повторяющийся звук.

## Ограничения sweep

Всего может одновременно играть не больше шести sweep-клипов. Частица с уже активным sweep не начинает новое взаимодействие; короткая и обычная пара, созданная одним касанием лежащей частицы, допускается совместно. Capture в этот учёт не входит и не ограничивается sweep-системой.

После принятого sweep выбираются два независимых случайных интервала:

- Для любых следующих sweep: база 100 мс с разбросом ±50%, то есть 50–150 мс.
- Для того же фактически выбранного OGG: база 500 мс с разбросом ±50%, то есть 250–750 мс.

Файл разрешается один раз до проверки и сохраняется для воспроизведения. Поэтому разные события, ссылающиеся на один OGG, не обходят его cooldown. Запросы во время паузы отбрасываются, не ставятся в очередь. Capture не запускает эти таймеры.

## Панорама

Положение берётся из видимого центра частицы по X: в центре экрана панорама 0, слева до −0,5, справа до +0,5. После создания звука адаптер на аудиопотоке настраивает его относительный OpenAL-источник без затухания от расстояния. Угол разведения ограничен, чтобы край экрана не давал жёсткую изоляцию одного канала.

Для стерео OGG используется `AL_SOFT_source_spatialize`, если расширение доступно. Если нет, один раз выводится предупреждение, а стереозвук может остаться по центру. Панорама применяется к sweep и capture.
