# Everfall — контекст проекта

Everfall 1.0.0 — законченный клиентский мод для декоративных частиц в меню Minecraft. Его задача — сделать интерфейс живым: частицы падают или поднимаются, ложатся на кнопки, реагируют на мышь и сопровождают взаимодействие звуком. На игровой мир и сервер мод не влияет.

Идентификатор мода — `everfall`, пакет — `com.yori3o.everfall`, лицензия — [MIT](LICENSE). Исходники: [yori3o/everfall](https://github.com/yori3o/everfall).

## Для игрока

Поддерживаются Fabric и NeoForge на Minecraft 1.21.1, 26.1, 26.2 и 26.3. Для 1.21.1 нужен Java 21, для 26.x — Java 25. Обязательная библиотека настроек — YACL; Mod Menu на Fabric даёт доступ к экрану настроек. На NeoForge он открывается из списка модов.

В поставке пять основных профилей: весна, лето, осень, зима и огонь. Автовыбор выбирает один из четырёх сезонных; огонь доступен вручную. Светлячки — отдельная особенность, которая может работать вместе с основным профилем. Ночью весной и летом они появляются автоматически, если включены в настройках.

По умолчанию частицы видны в меню вне игрового мира. Опция показа во время игры включает их в инвентаре, меню паузы и других игровых экранах. Можно менять количество, ветер, гравитацию, громкость и режим движения. Частицы на фоне рисуются под содержимым интерфейса и не взаимодействуют с ним.

Настройки сохраняются в `config/everfall.json5`. Профили можно добавлять и заменять ресурспаками или JSON-файлами в `config/everfall/profiles/`. Для добавления профиля на основе существующего поведения Java-код не нужен.

## Как проект работает целиком

Загрузчик запускает общий клиентский runtime. Тот загружает настройки и профили, определяет сезон и связывает интерфейс Minecraft с движками частиц.

Каждый кадр адаптер собирает размеры экрана, движение мыши и видимые препятствия. Основной движок рассчитывает частицы выбранного профиля; система дополнительных эффектов добавляет активные особенности. Они делят один общий лимит частиц. Результат передаётся отрисовке и звуковой системе Minecraft.

Профили описывают внешний вид и поведение, настройки игрока управляют текущей сценой, а автовыбор решает, какой сезонный профиль использовать. При выборе другого профиля применяются его встроенные настройки. Последующие ручные изменения сохраняются, пока профиль снова не сменится.

Перезагрузка ресурсов перечитывает определения, текстуры и звуки и сбрасывает частицы. Смена обычного экрана сохраняет летящие частицы, но убирает лежащие; изменение размера окна или режима координат пересоздаёт сцену.

Все восемь вариантов собираются из одного дерева исходников через Stonecutter. Общая логика находится в `core`, связь с Minecraft — в `mc`, точки входа загрузчиков — в `src/fabric` и `src/neoforge`. Наборы `src/mc/legacy` и `src/mc/modern` закрывают различия старого и нового GUI. Это отдельные сборки, а не один универсальный JAR.

## Короткие правила для coding-агента

1. Сначала прочитай относящуюся к задаче документацию и текущий код. Версия 1.0.0 завершена: не превращай старые идеи или предполагаемые улучшения в задачи без запроса владельца.
2. Сохраняй направление зависимостей: точки входа загрузчиков → адаптер Minecraft → `core`. В `core` нет Minecraft API; YACL-аннотации допустимы в конфигурационном POJO.
3. Различия Minecraft и низкоуровневые оконные вызовы держи в `mc/compat` и соответствующих наборах исходников. `src/mc/legacy` и `src/mc/modern` не обрабатываются Stonecutter как общий `src/main`; не помещай туда условные директивы в расчёте на препроцессор.
4. Имена Minecraft API проверяй по локальным исходникам нужной версии. Сохраняй mixin-цели, JSON-ключи и форматы профилей, если задача не требует их менять.
5. Не добавляй выделения объектов на каждую частицу в горячем цикле. Ошибки профилей обрабатывай при загрузке, с пропуском и понятным логом.
6. Не перезаписывай чужие незакоммиченные изменения и настройки ресурсов. Делай только запрошенную работу; не добавляй зависимости без необходимости.
7. После изменения кода собирай затронутые варианты; общие изменения проверяй на всех восьми. После изменения документации проверяй ссылки и примеры. Обновляй описание соответствующей системы, а этот файл оставляй обзорным.
